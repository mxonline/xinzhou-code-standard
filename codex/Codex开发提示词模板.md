# Codex 开发执行模板 v2.0

Z-Blog 插件任务默认先读取：

- `zblog/Z-Blog插件完整开发流程-v2.0.md`
- 当前项目真实代码
- 当前版本、分支、CHANGELOG 和相关测试

## 开发前

1. 读取现有代码结构，不凭空重写。
2. 确认当前版本、目标版本和影响范围。
3. 明确需要修改的文件、Hook、数据库和兼容要求。
4. 复杂任务按 PRD 执行；小 Bug 可走快速通道。

## 开发要求

- 优先使用 Z-Blog 原生 Hook / API / 模板机制。
- 不直接修改 `zb_system` 核心文件。
- 不过度设计。
- 不增加无必要文件和抽象层。
- 保持项目原有代码风格。
- 修改范围尽量局限在当前需求。
- 数据库升级必须考虑旧版本兼容和回滚风险。
- 不把计划描述为已执行结果。

## 默认测试

代码修改后优先执行高价值检查：

- PHP 语法检查
- 本次功能核心测试
- 数据库创建 / 升级检查（涉及数据库时）
- 插件启用 / 停用 / 必要升级路径
- 关键 Hook 触发检查
- PHP / SQL 错误检查
- 权限、CSRF、敏感信息检查（涉及对应风险时）

失败时直接定位、修复并重跑相关测试。

## 风险驱动扩展检查

以下工具不再机械地每次全部执行：

- PHPStan：公共接口、复杂重构、大版本或项目要求时启用。
- Semgrep：SQL、权限、上传、外部请求等安全敏感改动时优先启用。
- PHPUnit 完整套件：有完整测试体系、回归风险较高或正式发版前执行。
- 性能测试：高频 Hook、日志、统计聚合和数据库查询变化时执行。

## 完成后

1. 检查 diff 和无关文件。
2. 更新版本号和 CHANGELOG（需要发版时）。
3. 输出真实修改文件列表和测试结果。
4. Commit / Push，并运行仓库现有 CI。
5. CI 失败则分析日志、修复并重跑。
6. 将重要结果交给 ChatGPT 回写 Notion。

只有有真实执行证据的步骤才能标记“已完成”。
