# Z-Blog 插件功能验收规范 v1.0

本规范是 `Z-Blog插件完整开发流程-v2.0.md` 的强制补充规范，适用于所有 Z-Blog PHP 插件的新开发、升级、修复、优化、重构与正式发布。

目标：防止“代码存在、页面能打开、语法和 CI 通过，但真实功能没有按用户操作路径完整验证”的情况进入正式发布。

## 一、在完整流程中的位置

功能相关任务必须经过两层验收：

1. **开发阶段：功能实现验收**
2. **T5 / Release 前：最终功能回归验收**

以下均不能单独替代功能 PASS：

- 文件存在；
- PHP / JS 语法通过；
- HTTP 200；
- 页面无 Fatal / SQL Error；
- GitHub CI PASS；
- 数据表/字段存在；
- 单个函数或查询可调用。

任何冻结需求、正式功能或关键用户场景未完成真实验证：

```text
Functional Product Gate = BLOCKED
Release Gate = BLOCKED
```

禁止 Tag / Release / 正式 ZIP。

## 二、冻结需求必须建立功能验收矩阵

大版本、新插件、多模块功能必须建立：

```text
docs/<version>/functional-acceptance.md
```

每一项冻结需求至少记录：

- 需求 / 功能编号；
- 用户场景；
- 前置条件；
- 操作步骤；
- 预期结果；
- 实际结果；
- 自动测试证据；
- 本机实机证据（相关时）；
- PASS / BLOCKED / NOT REQUIRED；
- NOT REQUIRED 原因。

没有证据的 PASS 无效。

## 三、功能测试按“用户路径”而不是“代码函数”验收

功能验收必须回答：

1. 用户从哪里进入；
2. 用户执行什么操作；
3. 输入什么数据；
4. 页面/接口/数据库应该产生什么结果；
5. 异常输入或无数据时应该发生什么；
6. 用户是否能继续完成下一步。

禁止仅证明“后端函数有返回值”就判定正式功能完成。

## 四、通用功能验收清单

根据插件实际范围选用；涉及的项目必须验证。

### 生命周期

- 安装；
- 启用；
- 停用；
- 升级；
- 重复升级 / migration 幂等；
- 卸载策略（若插件支持）；
- 历史数据保留。

### 后台功能

- 页面入口；
- 权限；
- 设置读取；
- 设置保存；
- CSRF；
- 筛选；
- 搜索；
- 排序；
- 分页；
- 保存筛选；
- 详情；
- 新增/修改/删除（存在时）；
- AJAX；
- 导出；
- 空数据；
- 错误状态；
- 返回/刷新/重复提交。

### 数据采集 / 统计插件

涉及访问、日志、统计、蜘蛛、来源、性能等功能时，至少验证：

- 正常真人请求；
- 直接访问；
- Referer 来源；
- 搜索来源；
- 蜘蛛请求；
- 正常状态码；
- 404 / 4xx / 5xx；
- User-Agent；
- 无 User-Agent；
- IP / 可信代理（相关时）；
- 数据入库；
- 汇总；
- 查询；
- 时间范围；
- 历史数据；
- 实时数据（存在时）；
- 导出与页面统计一致性。

### 异常与边界

- 空值；
- 非法输入；
- 超长输入；
- 重复请求；
- 无权限；
- 依赖不可用；
- 数据缺失；
- 旧版本数据；
- 可恢复错误。

## 五、前后端必须做端到端对应验收

如果功能存在后台 UI，则必须验证：

```text
用户操作 UI
→ 请求 / AJAX
→ 后端处理
→ 数据结果
→ UI 返回正确状态
```

只测 UI 不测后端结果，不能 PASS。
只测后端函数不实际走 UI 用户路径，也不能 PASS。

## 六、测试数据与真实数据

开发验收可以使用测试请求、测试记录或隔离数据，但必须：

- 明确标记测试数据；
- 不破坏真实历史数据；
- 不把测试结果伪装成真实用户数据；
- 正式验收至少包含正常用户场景；
- 用户明确禁止的数据库管理操作不得执行。

无法执行的专项测试只能标记 `NOT REQUIRED（用户约束）` 或 `BLOCKED`，不得伪装 PASS。

## 七、功能回归

修复一个功能后必须检查：

- 当前功能是否修复；
- 相邻功能是否受影响；
- 原本通过的核心流程是否仍通过。

大版本 T5 必须重跑全部冻结 P0 / 必须功能，而不是只重跑最后修改的页面。

## 八、功能 PASS 的最低证据

每个正式功能至少应有一种或多种真实证据：

- 自动测试输出；
- 本机 HTTP / API 验证；
- 本机 Z-Blog 实际操作结果；
- 数据库非破坏性验证；
- 日志；
- 截图（仅视觉/交互相关时）；
- GitHub CI（只能作为补充，不能替代必须实机）。

## 九、T5 最终功能门禁

正式发布前必须得到：

```text
Frozen Requirements Matrix: PASS
Functional Product Gate: PASS
UI Product Gate: PASS（存在后台 UI 时）
Local Runtime: PASS / NOT REQUIRED（有明确理由）
GitHub CI: PASS
Release Gate: PASS
```

任意冻结功能为 BLOCKED：

```text
FINAL: INCOMPLETE
RELEASE: NOT RELEASED
```

不得因为“剩余功能不多”“只是边角功能”而提前发布。
