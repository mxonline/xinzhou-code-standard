# Z-Blog 插件开发规范

本文件保留 Z-Blog 插件开发的基础原则。完整执行流程统一以：

`zblog/Z-Blog插件完整开发流程-v2.0.md`

为准。

## 开发原则

- 优先使用 Z-Blog 原生机制。
- 不直接修改 `zb_system` 核心文件。
- 保持代码简单。
- 避免过度封装。
- 不增加无必要文件。
- 不重复实现已有功能。
- 修改前读取现有代码和项目记录。
- 修改后执行与风险匹配的测试。
- 数据库升级保留旧数据兼容。
- GitHub 真实代码状态优先于聊天描述。

## 默认执行方式

用户提出开发、修改、修复或优化需求后，由 ChatGPT 按 v2.0 总控流程自动推进：

需求识别 → Notion / GitHub 状态恢复 → 方案 / PRD → Codex / 开发工具执行 → 快速测试 → 风险驱动检查 → Git / CI → Notion 同步 → 发布准备。

正常流程不逐步询问“下一步”。

## 禁止事项

- 未读取现有代码就整体重写插件。
- 无意义增加文件、类和抽象层。
- 大量模板化注释和 AI 风格占位代码。
- 未做迁移方案直接删除或重构数据表字段。
- 未经验证就宣称代码、CI、Notion 或本地测试已执行。
- 小修改机械运行与风险无关的全部重型检查。
